# 0005. Сервис paper-проверки идей (`paperd`)

## Контекст

Идеи 1 (размещения) и 10 (рекомендации дивидендов) подтверждены на истории (0007, 0011, 0012).
Дальше — проверка вперёд на виртуальных деньгах, без ручных действий, все идеи параллельно,
с админкой. Работает на хосте бота (`bcs-trading-bot`), доступ — токен как в боте.

## Решение

- **Одна репа, отдельный бинарь** `cmd/paperd`. Каркас — `internal/paper` (запуск по расписанию,
  журналы, оценка, админка); стратегии — `internal/feature/paperstrat`, каркас о них знает только
  интерфейс `paper.Strategy`.
- **Live = бэктест «на вчера».** Стратегия — функция `Ops(asOf)`: все операции с даты старта по
  данным, известным к `asOf`. Раз в сутки (и по кнопке) сервис пересчитывает и дописывает новые
  операции в журнал `data/paper/<стратегия>.jsonl` через `ledger.Reconcile`: изменённое прошлое
  останавливает стратегию и шлёт тревогу. Отдельного «живого» кода нет — расходиться нечему.
- **Дневной шаг.** Решения по дневным барам ISS (open дня входа, close дня выхода) — как в
  проверенных бэктестах; внутридневные данные не нужны. Пересчёт в 02:00 МСК за прошедший день.
- **Хранилище — JSONL-журналы**, не SQLite: операций сотни, всё считается из журнала на лету.
- **Админка** — встроенный HTTP (по умолчанию `127.0.0.1:8092`), `ADMIN_TOKEN` обязателен при
  bind не на localhost; токен `Bearer` или `?access_token=` (ставит cookie). Страницы: сводка
  стратегий против бенчмарков, позиции, журнал, кривая капитала. Только чтение + «пересчитать».
- **Тревоги** — Telegram (`TG_BOT_TOKEN`, `TG_CHAT_ID`, тот же `/etc/trading-bot/env`): ошибка
  пересчёта, расхождение журнала.
- **Стратегии стартуют с регистрации** (0013): правило, сумма на сделку, срок, критерий.

## Последствия

- Логика сверки журнала переезжает из `feature/portfolio` в `internal/ledger` — её используют
  и `run`/`diary`, и каркас `paper`.
- Решение в момент события (внутри дня) сервис не принимает — для этих идей не нужно; для
  внутридневных идей понадобится другой каркас (ближе к боту).
